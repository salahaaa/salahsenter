# تقرير إصلاح نافذة إدارة الإعلانات وربط إعلانات المتاجر ببنر الرئيسية — 2026-07-02

## المشكلة التي تم فحصها
أبلغ المستخدم أن نافذة **إدارة الإعلانات** في لوحة الأدمن بطيئة وعند فتحها قد لا تظهر، ويريد التأكد من:

1. سبب البطء.
2. أن رفع إعلان/بانر من الأدمن يظهر في لوحة البنر في الواجهة الرئيسية.
3. أن الأدمن يستطيع استقبال طلبات إعلانات المتاجر ونشرها في لوحة البنر الرئيسية.

---

## سبب البطء المؤكد
تم فحص قاعدة البيانات، وظهر أن صفحة `/admin/ads` كانت تحمل صور الإعلانات مباشرة من أعمدة قاعدة البيانات، وبعض الصور محفوظة كـ base64 داخل قاعدة البيانات.

نتيجة الفحص:

| المصدر | العدد | صور base64 | حجم base64 تقريبي |
|---|---:|---:|---:|
| banners | 3 | 3 | 6,175,638 حرف |
| announcements | 7 | 1 | 2,058,546 حرف |
| ad_campaigns.creative.imageUrl | 2 | 0 | 0 |

المعنى: صفحة إدارة الإعلانات كانت قد تسحب أكثر من 8MB من الصور داخل HTML/SSR، وهذا سبب واضح للبطء أو عدم ظهور الصفحة بسرعة.

---

## الإصلاحات المنفذة

### 1) منع تحميل صور base64 داخل صفحة إدارة الإعلانات
تم تعديل صفحة:

```txt
app/admin/ads/page.tsx
```

بحيث لا تسحب الصور الخام مباشرة، بل تستخدم proxy آمن:

```txt
/api/media/inline
```

النتيجة: الصفحة تعرض الصور، لكن لا تحمل كتلة base64 الضخمة داخل HTML.

---

### 2) إضافة دعم صور إعلانات المتاجر داخل media proxy
تم تعديل:

```txt
app/api/media/inline/route.ts
lib/inline-media.ts
```

لإضافة دعم:

```txt
entity=adCampaigns
field=creativeImageUrl
```

حتى إذا كان إعلان التاجر يحتوي على صورة داخل `creative.imageUrl` يمكن عرضها عبر proxy دون تضخيم الصفحة.

---

### 3) عرض طلبات إعلانات المتاجر داخل صفحة إدارة الإعلانات نفسها
كانت طلبات إعلانات المتاجر موجودة في صفحة منفصلة/داخلية، ولم تكن واضحة داخل نافذة `/admin/ads`.

تم دمجها الآن في صفحة إدارة الإعلانات:

```txt
/admin/ads
```

ويظهر فيها:

- اسم الإعلان.
- اسم المتجر.
- نوع الإعلان.
- صورة البنر إن وجدت.
- الحالة.
- الميزانية.
- هل تم ربطه ببنر رئيسي أم لا.
- أزرار الإدارة.

---

### 4) زر اعتماد ونشر في البنر الرئيسي
تم تحسين مكون:

```txt
components/admin/ad-campaign-admin-panel.tsx
```

لإظهار زر خاص عندما يكون نوع الإعلان:

```txt
homepage_banner
```

الزر:

```txt
اعتماد ونشر في البنر
```

عند الضغط عليه:

- يتم اعتماد إعلان التاجر.
- يتم إنشاء/تحديث سجل في جدول `banners`.
- يتم ضبط `placement = homepage_promo`.
- يتم تفعيل البانر `status = active`.
- يتم حفظ رقم البانر داخل `ad_campaigns.creative.publishedBannerId` لمنع التكرار.
- يتم تحديث كاش الصفحة الرئيسية.

---

### 5) نشر إعلانات المتاجر في الصفحة الرئيسية فعلياً
تم تعديل:

```txt
app/api/admin/ad-campaigns/route.ts
```

الآن عند اعتماد إعلان متجر من نوع `homepage_banner` يتم نشره في لوحة البنر الرئيسية تلقائياً.

كما تم تعديل:

```txt
lib/home-visibility.ts
```

حتى إعلانات المتاجر المعتمدة التي تظهر في أقسام الإعلانات لا تفقد صورتها، وتُعرض عبر proxy إذا كانت صورة base64.

---

### 6) رفع بانر من الأدمن يظهر فوراً في الرئيسية
تم تعديل:

```txt
components/admin/banner-form.tsx
```

الآن الحالة الافتراضية عند رفع بانر من الأدمن هي:

```txt
active — يظهر فوراً في لوحة البنر الرئيسية
```

بدلاً من أن تكون مسودة لا تظهر.

كما بقي المكان الافتراضي:

```txt
homepage_promo
```

وهو المكان المستخدم في لوحة البنر المتحركة في الواجهة الرئيسية.

---

### 7) تصحيح صلاحية API
كانت صفحة الأدمن تطلب `ads.manage`، لكن بعض APIs الخاصة بالبانرات والإعلانات كانت تطلب `announcements.manage`، وهذا قد يجعل الصفحة تظهر لكن الحفظ/التفعيل لا يعمل لبعض موظفي الإدارة.

تم توحيد APIs الخاصة بإدارة الإعلانات لتستخدم:

```txt
ads.manage
```

في:

```txt
app/api/admin/banners/route.ts
app/api/admin/banners/[id]/route.ts
app/api/admin/announcements/route.ts
app/api/admin/announcements/[id]/route.ts
```

---

### 8) إشعار الأدمن عند إرسال التاجر طلب إعلان
تم تعديل:

```txt
app/api/merchant/ad-campaigns/route.ts
```

بحيث عند إرسال التاجر طلب إعلان يتم إنشاء تنبيه للأدمن بعنوان مناسب ورابط إلى:

```txt
/admin/ads
```

## فحص ظهور البانرات في الصفحة الرئيسية عبر الكود الحالي
تم تشغيل تحميل بيانات الرئيسية محلياً على قاعدة التجربة، والنتيجة أن صور البانرات أصبحت تخرج بهذا الشكل:

```txt
/api/media/inline?entity=banners&field=imageUrl&id=...
```

وليست:

```txt
data:image/...base64
```

وهذا يؤكد أن الواجهة الرئيسية ستعرض البانر عبر مسار خفيف وآمن.

## الخلاصة
سبب البطء كان تحميل صور base64 كبيرة مباشرة داخل صفحة إدارة الإعلانات. تم إصلاح ذلك باستخدام media proxy، وتم دمج طلبات إعلانات المتاجر داخل نفس صفحة إدارة الإعلانات، وأصبح بإمكان الأدمن اعتماد إعلان التاجر ونشره مباشرة في لوحة البنر الرئيسية.

لا توجد Migration مطلوبة لهذا الإصلاح؛ التعديل برمجي/واجهات/API فقط.
