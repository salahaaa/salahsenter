# تطوير اكتشاف المنتجات — أصناف مشابهة ومحلات تبيع نفس الصنف

**التاريخ:** 12 يوليو 2026
**الحالة:** مكتمل برمجيًا ومحليًا؛ لم يُنشر أو يُختبر على بيانات إنتاج.

## الهدف

رفع قابلية اكتشاف المنتجات ومساعدة العميل على المقارنة داخل المول، دون الادعاء بأن بديلًا قريبًا هو نفس المنتج إلا عند وجود دليل كافٍ.

## ما نُفذ

### 1) محرك توصيات قابل للتفسير

أضيف:

```text
lib/discovery/product-similarity.ts
lib/discovery/product-discovery.ts
```

يقارن المنتج المرجعي بالمنتجات العامة المتاحة فقط عبر ترتيب الأدلة التالية:

1. **باركود مشترك** → `تطابق مؤكد`.
2. **اسم مطابق + علامة تجارية مطابقة** → تطابق قوي/دقيق.
3. تداخل كلمات الاسم بعد تطبيع العربية + العلامة التجارية + اسم الفئة + التوفر.
4. لا تستخدم الفئة وحدها لادعاء التطابق؛ تظهر فقط كبديل مشابه.

تطبيع العربية يعالج اختلافات مثل الهمزات والتشكيل والـ ــ والياء/الألف المقصورة، ويزيل كلمات عامة غير مفيدة للمطابقة.

### 2) API عام محدود ومخزن مؤقتًا

المسار الجديد:

```text
GET /api/products/{id}/discovery
```

خصائصه:

- يقبل UUID صالحًا فقط.
- rate limit: 90 طلبًا لكل IP خلال 15 دقيقة.
- يعرض منتجات متاجر نشطة ومنشورة وبمخزون متاح.
- cache لمدة منتج عامة، مع tags المنتجات والمتاجر؛ تتأثر تلقائيًا بإبطال كاش المنتجات/المتاجر الموجود.

### 3) تجربة صفحة المنتج

أضيف قسم تفاعلي أسفل صفحة المنتج العامة يعرض:

```text
محلات تبيع نفس الصنف
بدائل قريبة من محلات أخرى
أصناف مشابهة قد تعجبك
```

كل بطاقة تعرض المتجر والسعر الابتدائي والتقييم والتوفر وسبب التشابه. أمثلة الأسباب:

```text
نفس الباركود
اسم مطابق
نفس العلامة التجارية
ضمن نفس الفئة
تشابه في وصف المنتج
```

ويظل وصف `تطابق مؤكد` محصورًا في الباركود المشترك فقط، بينما النتائج الأقل ثقة تعرض كتطابق قوي أو بديل مشابه.

### 4) قياس جودة التوصيات

أضيف حدث funnel:

```text
product_recommendation_click
```

ويتم تسجيله عند فتح بطاقة مقترحة، مع مصدر الاقتراح ومستوى الثقة ومعرّفات المصدر/النتيجة، دون حفظ visitor ID خام.

تظهر الآن في تقارير الأدمن والتاجر:

```text
نقر توصيات
معدل نقر التوصيات مقابل مشاهدات المنتجات
```

وهذا يسمح بقياس ما إذا كانت التوصيات مفيدة قبل تطوير ترتيبها لاحقًا.

## ما لا يدعيه هذا التطوير

- ليس نظام ML أو vector embeddings ولا يستخدم مزود AI خارجيًا أو بيانات شخصية للتوصية.
- لا يقارن السعر بعد تحويل مستقل لإعدادات كل متجر؛ يعرض السعر الأساسي ضمن نظام العملات الحالي للواجهة.
- لا يضمن أن البديل يؤدي نفس المواصفات؛ العميل يجب أن يراجع المواصفات والضمان والمتغيرات قبل الشراء.
- لا يوجد اختبار على كتالوج أو زيارات إنتاج حقيقية من هذه الجلسة.

## التطويرات المنطقية التالية

1. مقارنة مواصفات منظمة (RAM/المقاس/اللون/الضمان) حسب القطاع، لا النص فقط.
2. ترتيب شخصي opt-in مبني على النقرات والمفضلة والشراء، مع ضوابط خصوصية واضحة.
3. Semantic search / embeddings بعد اختيار مزود AI أو vector database وسياسة تكلفة واحتفاظ بالبيانات.
4. مقارنة سعر عبر العملات وإظهار فرق السعر والشحن عند توفر قواعد موحدة.
