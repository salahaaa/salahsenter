# تصميم تغيير: Merchant Operations Center

**التاريخ:** 2026-07-15

## المشكلة
لوحة التاجر الحالية غنية بالبيانات، لكنها تحتوي مركز أدوات كبيراً يعرض عشرات الوظائف معاً، ولا تعرض انتقال المتجر النشط أو ملخص محفظة الفروع والأنشطة بصورة كافية. هذا يزيد الحمل المعرفي ويخفي الإجراءات اليومية المهمة.

## الهدف
تحويلها إلى لوحة تشغيل يومية ذات تسلسل:
```text
المتجر النشط
→ ما يحتاج إجراء الآن
→ أداء ومبيعات
→ محفظة المتاجر والالتزامات
→ أدوات مصنفة وقابلة للبحث
```

## النطاق
1. Store switcher للحسابات متعددة المتاجر والفروع، يستخدم cookie `merchant_store_id` والمسار الحالي المعتمد.
2. Portfolio summary: عدد المتاجر، النشطة، إجمالي المبيعات المخزنة، والانتقال لكل متجر.
3. Financial snapshot: كشوف منصة معلقة للمتجر الحالي وإجمالي الالتزامات المرئية للتاجر عبر محفظته، دون payout أو تغيير مالي.
4. Toolbox client-side tabs/search لتقليل عرض كل الأدوات دفعة واحدة.
5. لا تغيير في RBAC؛ الصفحات النهائية تبقى مصدر الحماية، والروابط لا تمنح صلاحية.

## التوسع والصيانة
- يستخدم dashboard queries محدودة ومفهرسة حسب merchant/store/status.
- لا جدول أو migration جديد.
- لا يغير مصدر حقيقة المبيعات أو العقود أو الكشوف؛ يعرض summary فقط.
- Store switcher يستدعي endpoint موجود ومراجع الصلاحية.

## التوافق
- حساب متجر واحد يرى نفس اللوحة مع selector بسيط.
- حساب متعدد يرى نفس البيانات scoped للمتجر المختار، ولا تخلط منتجات/طلبات/مخزون المتاجر.
