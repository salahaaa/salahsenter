# تقرير نقل قوالب النشاط إلى الإضافات الذكية وآلية حفظها — 2026-07-03

## الفكرة المعتمدة
تم اعتماد اقتراح أن تكون قوالب النشاط داخل نافذة واضحة في:

```txt
لوحة التاجر → الإضافات الذكية
```

حتى تكون نقطة البداية الطبيعية للتاجر قبل إضافة المنتجات.

---

## الآلية الجديدة

### 1) التاجر يدخل إلى الإضافات الذكية
المسار:

```txt
/merchant/smart-tools
```

سيجد الآن بطاقة جديدة:

```txt
نافذة قوالب النشاط الذكية
```

وفيها زر:

```txt
فتح نافذة القوالب
```

---

### 2) النظام يقترح القالب المناسب تلقائياً
يقرأ النظام:

- اسم المتجر.
- وصف المتجر.
- النشاط/الأقسام المتوفرة.

ثم يقترح القوالب المناسبة مثل:

- ملابس / أزياء.
- أحذية.
- أدوات منزلية.
- مواد غذائية وتموين.
- خضار وفواكه.
- مخبز وحلويات.
- ألبان وأجبان.
- لحوم وأسماك.
- إلكترونيات.
- صيدلية.
- خدمات.

---

## هل تحفظ القوالب ضمن إعدادات المتجر؟
نعم. عند اختيار التاجر لقالب نشاط، لا يبقى القالب مجرد عرض أو اقتراح مؤقت، بل يتم حفظه فعلياً داخل إعدادات المتجر والجداول التشغيلية.

يتم إنشاء/تحديث:

```txt
categories              الأقسام
units                   الوحدات
sizes                   المقاسات
colors                  الألوان
product_attributes      المتغيرات
product_attribute_values قيم المتغيرات
```

وبالتالي عند إضافة صنف/منتج جديد، يرى التاجر هذه القيم جاهزة ولا يحتاج لإضافتها مرة أخرى.

## أمثلة عملية

### تاجر ملابس
عند تطبيق القالب، يتم حفظ:

```txt
أقسام: رجالي، نسائي، أطفال، أحذية، إكسسوارات
وحدات: قطعة، طقم
مقاسات: XS, S, M, L, XL, XXL
ألوان: أسود، أبيض، أزرق، رمادي، بني، وردي
متغيرات: المقاس، اللون، الخامة
```

### تاجر أحذية
يتم حفظ:

```txt
أقسام: أحذية رجالية، أحذية نسائية، أحذية أطفال، أحذية رياضية، أحذية رسمية
وحدات: زوج، قطعة
مقاسات: 36 حتى 45
ألوان: أسود، أبيض، بني، رمادي، أزرق
متغيرات: المقاس، اللون، الاستخدام
```

### تاجر مواد غذائية
يتم حفظ:

```txt
أقسام: الأرز والحبوب، الزيوت والسمن، المعلبات، البقوليات، السكر والطحين، التوابل والبهارات
وحدات: كيلو، كيس، كرتون، عبوة، باكت
أحجام/مقاسات: 250 جم، 500 جم، 1 كيلو، 5 كيلو، 10 كيلو، 25 كيلو
متغيرات: الوزن، العبوة، نوع البيع
```

## API الجديد

### GET
```txt
GET /api/merchant/activity-templates
```

يرجع القوالب المتاحة والقوالب المقترحة للمتجر.

### POST
```txt
POST /api/merchant/activity-templates
```

Body:

```json
{
  "templateKey": "fashion"
}
```

يقوم بتطبيق القالب وحفظ البيانات داخل إعدادات المتجر.

---

## منع التكرار
تم جعل الحفظ آمناً:

- إذا كان القسم موجوداً لا يتكرر.
- إذا كانت الوحدة موجودة يتم تحديثها.
- إذا كان المقاس موجوداً يتم تحديثه.
- إذا كان اللون موجوداً يتم تحديثه.
- إذا كانت الخاصية موجودة بنفس الكود يتم تحديثها.
- إذا كانت قيمة المتغير موجودة يتم تحديثها.

يعني لو ضغط التاجر القالب مرتين لا تتكرر البيانات بشكل مزعج.

## علاقة القوالب بإضافة منتج جديد
بعد تطبيق القالب، تظهر القيم في:

```txt

محرر المنتج
إضافة المنتج
المتغيرات والقيم
```

ويستطيع التاجر اختيارها عند بناء المتغيرات، بدلاً من إنشائها يدوياً.

## الخلاصة
تم اعتماد الآلية المقترحة:

- القوالب موجودة الآن داخل الإضافات الذكية.
- عند تطبيق القالب، تحفظ البيانات فعلياً في إعدادات المتجر.
- تظهر للتاجر لاحقاً عند إضافة منتج جديد.
- القوالب لا تنشئ منتجات تلقائياً؛ هي تجهز بنية المتجر فقط.
- التاجر يستطيع تطبيق أكثر من قالب إذا كان متجره متعدد النشاط.
