# تقرير مرحلي: تطوير العروض كمنتجات مخزنية

**التاريخ:** 2026-07-16  
**الحالة:** تقرير مرحلي مؤرشف؛ راجع التقرير النهائي `OFFERS_INVENTORY_PRODUCT_AND_PUBLICATION_IMPLEMENTATION_REPORT_2026-07-16_AR.md`. لم تطبق أي migration على Staging أو Production.

## ما اكتمل قبل بدء الإصلاح

1. فحص شامل لمسار العروض من التاجر إلى الإدارة وواجهة المتجر والرئيسية.
2. توثيق الفجوات الحرجة في:
   ```text
   docs/OFFERS_SYSTEM_END_TO_END_AUDIT_2026-07-16_AR.md
   ```
3. تثبيت تعديل سابق: الجناح هو قطاع النشاط الوحيد في طلب فتح المتجر، بلا اختيار قطاع ثانٍ للتاجر.

## ما تم بناؤه في حزمة العروض الحالية حتى الآن

### نموذج البيانات المحلي

تم تجهيز migration جديدة محلياً:

```text
0082_offer_inventory_products_publication_lifecycle
```

وتضيف أساس دورة العرض الجديدة:

- ربط العرض بمنتج مخزني مولد:
  ```text
  store_offer_collections.offer_product_id
  store_offer_collections.offer_variant_id
  ```
- فصل وجهة النشر عن حالة النشر:
  ```text
  publication_target = storefront | homepage
  publication_state = storefront_live | homepage_review | homepage_approved | ...
  ```
- سجل ربط بيع منتج العرض بالطلب:
  ```text
  store_offer_order_allocations
  ```

### دورة المنتج المخزني

بدأت خدمة مركزية جديدة في:

```text
lib/offers/offer-product-inventory.ts
```

وظيفتها عند تجميع العرض:

1. خصم كميات مكونات العرض من متغيرات منتجاتها الأصلية داخل transaction.
2. إنشاء منتج فعلي جديد باسم العرض ضمن تصنيف «عروض المتجر».
3. إنشاء متغير مخزون لهذا المنتج بعدد وحدات العرض المحددة.
4. تسجيل حركات مخزون واضحة:
   ```text
   component products → deduct
   offer inventory product → add
   ```
5. تجهيز تفكيك وحدات العرض غير المباعة وإرجاع المكونات إلى المخزون.

### وجهتا النشر

بدأت إعادة تنظيم السياسة لتصبح:

| اختيار التاجر | السلوك المستهدف |
|---|---|
| نافذة عروض متجري | نشر مباشر داخل واجهة متجره فقط بعد تحقق المخزون والسعر |
| الرئيسية ومنصة العروض | طلب مراجعة للإدارة، لا يظهر للعامة قبل الاعتماد |

كما أزيل من نموذج العرض مفهوم أن التاجر يحدد بنفسه `isPromoted`؛ الظهور الممول يبقى مساراً إدارياً/تجارياً مستقلاً.

### حماية ERP

تم إدخال حاجز تصميمي: المتاجر التي يكون ERP فيها مصدر حقيقة المخزون لا يسمح لها النظام حالياً بتجميع عرض مخزني مباشرة داخل المنصة، حتى لا تتعارض المنصة مع مخزون ERP. تحتاج هذه الحالة لاحقاً إلى DTO/connector معتمد للباقة داخل ERP.

## ما لم أعتبره مكتملاً بعد

لا تزال الحزمة تحتاج إكمال وربط واختبار قبل أن أقول إنها جاهزة:

1. إنهاء واجهة اختيار المتغير المخزني لكل مكون في العرض.
2. إنهاء ربط شراء منتج العرض بالطلب العادي والتأكد أن سعر العرض هو السعر الخادمي النهائي.
3. إنهاء دورة الإلغاء/الاسترجاع والتفكيك وحالات انتهاء العرض.
4. فصل استعلامات واجهة المتجر عن استعلامات الرئيسية بشكل كامل وفق وجهة النشر.
5. إنهاء واجهة مراجعة الأدمن ورسالة الرفض والجدولة.
6. كتابة اختبارات وحدات وتكامل لدورة:
   ```text
   assemble → publish store / request homepage → approve → order → cancel → dissolve
   ```
7. تشغيل الفحص الكامل بعد الإكمال:
   ```text
   lint / typecheck / test / migrations verify / drizzle check / security verify
   ```
