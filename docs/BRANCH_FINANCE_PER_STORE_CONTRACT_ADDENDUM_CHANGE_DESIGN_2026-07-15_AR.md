# تصميم تغيير: دورة مالية مستقلة لكل فرع عبر ملحق العقد

**التاريخ:** 2026-07-15  
**القرار المعتمد:** كل فرع يملك دورة إيرادات مستقلة، وعقده المالي يكون ملحقاً للعقد الرئيسي.

## الفجوة الحالية
مسار الفروع القديم ينشئ `store_rent_invoices` وإيجاراً منفصلاً للفرع، لكنه لا ينشئ `merchantRevenueTerms` أو عمولة/هجين ولا يدخل بصورة موحدة في `platform-revenue`. لا يجوز إضافة terms بالتوازي من دون ضبط، لأن ذلك قد يسبب فوترة إيجار مكررة.

## النموذج الجديد للفروع
```text
طلب فرع
→ تسعير إدارة (إيجار / عمولة / هجين + due/grace)
→ ملحق عقد للفرع تحت العقد الرئيسي
→ توقيع التاجر وPDF أرشيفي
→ اعتماد إداري للملحق
→ Revenue Terms + rental compatibility + تفعيل الفرع
→ كشف منصة مستقل للفرع وإجمالي عبر حساب التاجر
```

## العقد
- العقد الأصلي يبقى مملوكاً للمتجر الرئيسي.
- ملحق الفرع مرتبط بالعقد الأصلي (`parent_contract_id`) لكنه يذكر رقم الفرع وموقعه ونموذج إيراد الفرع ومدته وشروطه.
- لا ينشط الفرع أو terms المالية قبل توقيع الملحق ووجود PDF أرشيفي جاهز واعتماد الإدارة.
- يستخدم توقيع/أرشفة addendums الحالية ولا يفتح مسار توقيع أضعف أو موازياً.

## المال
- `monthly_rent`, `sales_commission`, `hybrid` تضبط لكل فرع على حدة.
- `merchantRevenueTerms` تنشأ للـ branch store فقط بعد اعتماد الملحق.
- `storeRentalAgreements` ينشأ بوضع `consolidatedBilling=true` للتوافق، فلا ينشئ مسار الإيجار القديم فاتورة مستقلة ثانية.
- كشوف `platform-revenue` تبقى per-store، ولذلك يظهر كل فرع بسطر/كشف مستقل، ويمكن تجميع الإجمالي حسب merchant في لوحة الإدارة/التاجر دون خلط مصادر الفوترة.

## التوافق مع الفروع القديمة
- الفرع القديم الذي يحمل `financial_mode=legacy_branch_invoice` لا يحول تلقائياً، وتبقى فواتيره التاريخية سليمة.
- الفرع الجديد يستخدم `financial_mode=platform_revenue`.
- تحويل فرع قديم يحتاج إجراء إداري لاحق: إنشاء ملحق، توقيع، نقطة قطع مالية، ثم إغلاق legacy schedule؛ خارج هذه الدفعة لتفادي الازدواج.

## التوسع والصيانة
- حقول مرجعية على profile للملحق والعقد وRevenueTerms، وفهارس للحالة/النمط.
- لا توجد queue أو معالجة غير متزامنة جديدة؛ تفعيل الملحق transaction مع locks/uniqueness حيث يلزم.
- يُمنع التفعيل إن لم يجهز PDF الموقع أو لم تكن الحالة `signed`.
- تدقيق وإشعارات لكل طلب/إنشاء ملحق/توقيع/اعتماد/تفعيل مالي.

## التراجع
- الترحيل إضافي. إيقاف استخدام المسار الجديد يعيد الفروع الجديدة إلى pending ولا يحذف العقد أو terms أو الكشوف.
- لا تحذف legacy invoices أو statements.
