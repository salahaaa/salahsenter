# تصميم تغيير: طلبات الظهور التجاري وتفعيل الأدمن اليدوي

**التاريخ:** 2026-07-15  
**القرارات المعتمدة:**
- التاجر يرسل طلباً أو الأدمن ينشئ الظهور مباشرة.
- تفعيل الحملة المدفوعة بالمدة قرار إداري يدوي لكل حملة؛ يمكن للأدمن التفعيل بعد إصدار فاتورة أو بعد تأكيد سدادها، ولا يعتمد النظام أحد الشرطين تلقائياً.

## الهدف
إكمال المثال التجاري: متجر لا يستوفي قواعد الظهور العضوي يمكنه طلب مساحة رئيسية مدفوعة. لا يصبح جزءاً من الترتيب العضوي؛ ينشأ ظهور تجاري مستقل وموسوم ومحدود بوقت/ساعات/عدادات.

## دورة العمل
```text
Merchant request (submitted)
→ Admin quote / review (quoted)
→ Admin approves and creates PAUSED commercial campaign + accrued ad ledger line
→ Invoice / payment is handled through the approved finance workflow
→ Admin activates manually at the chosen milestone
→ engine runs schedule/caps
→ auto-pause at end/cap or manual pause
```

## البيانات
ترحيل إضافي `0072` ينشئ `home_exposure_requests` مع:
- المتجر والتاجر والموضع والهدف.
- الفترة والجدولة والمحتوى الإبداعي.
- نموذج الإيراد المطلوب.
- العرض السعري، العملة، سياسة التفعيل `manual_admin`.
- مرجع حملة الظهور وسطر دفتر الإعلان عند التحويل.
- حالة العمل، ملاحظة المراجعة، المراجع والتواريخ.

## المال والحوكمة
- السعر المعتمد يضيف سطر `ad_billing` بحالة `accrued` وبمفتاح idempotent بعد تحويل الطلب فقط.
- هذا **استحقاق إعلان** وليس خصماً من العميل أو دليلاً على التحصيل.
- لا تصدر الواجهة فاتورة تلقائياً ولا تعتبرها مدفوعة.
- التفعيل يبقى يدوياً لدى الأدمن؛ لذلك يدعم الحالات التي تبدأ بعد الفاتورة أو بعد السداد من دون تخمين حالة مالية.

## الصلاحيات والأمان
- التاجر: صلاحية إدارة إعلانات متجره، ولا يستطيع تحديد السعر أو التفعيل أو تغيير الطلب بعد تحويله.
- الأدمن: `ads.manage` و`home.manage` للمراجعة والتحويل، مع audit log وإشعار للطرفين.
- لا يمكن للتاجر اختيار متجر آخر أو تضمين أسرار/وسائل دفع ضمن الطلب.

## التوسع والصيانة
- فهارس على المتجر/الحالة، والتاجر/الحالة، والحملة تمنع مسحاً كاملاً للقائمة.
- التحويل transaction مع unique request/campaign وevent key فريد لمنع إنشاء حملة أو رسم مكرر عند إعادة المحاولة.
- لا يوجد worker أو queue جديد؛ التحويل صغير ومعاملته ذَرّية.
- لا تغير هذه الإضافة مسار CPC/CPM أو أموال مبيعات العملاء.

## التوافق والتراجع
- إضافي فقط ولا يكسر الحملات الموجودة.
- يمكن إغلاق قبول الطلبات بإزالة رابط التاجر؛ الطلبات والحملات السابقة تبقى قابلة للمراجعة.
- التراجع في DB: إزالة القيود والفهارس ثم الجدول بعد إيقاف المسارات الجديدة؛ لا تحذف سطور دفتر قائمة.
