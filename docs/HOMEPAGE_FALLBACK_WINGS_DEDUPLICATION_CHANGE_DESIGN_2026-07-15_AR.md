# تصميم تغيير: منع تكرار أجنحة الصفحة الرئيسية عند كتالوج فارغ

**التاريخ:** 2026-07-15  
**النطاق:** بطاقات «أحدث الإضافات» في الصفحة الرئيسية فقط.

## المشكلة المؤكدة
عندما لا توجد منتجات منشورة، تستخدم الصفحة الرئيسية قائمة الأجنحة كبديل مرئي. وكانت الدالة السابقة تضيف `fallbackWings` إلى `wings` مرة أخرى. وبما أن `wings` تساوي بالفعل `fallbackWings` عند عدم وجود أجنحة منشورة، كانت النتيجة سجلات مكررة بالمفاتيح نفسها (`w1` إلى `w4`) وتحذير React ومحتوى مكرر.

## القرار
- تبقى قائمة الأجنحة المختارة للواجهة هي المصدر الوحيد للبديل عند عدم وجود منتجات.
- لا يجري دمج بيانات افتراضية إضافية داخل بطاقات «أحدث الإضافات».
- تُزال التكرارات دفاعياً حسب `id` ثم `slug` قبل العرض.
- تُنقل قاعدة البناء إلى وحدة نقية قابلة للاختبار (`lib/home/latest-cards.ts`) كي لا تعتمد الاختبارات على واجهة React.

## حساب التوسع والصيانة
- **التوسع:** العملية خطية O(n) على قائمة صغيرة محدودة بستة بطاقات، ولا تضيف طلبات قاعدة بيانات أو ذاكرة مؤقتة أو طوابير أو تخزيناً.
- **الصيانة:** مصدر واحد لمنطق fallback، واختبار يمنع عودة الدمج المكرر. لا توجد مفاتيح إعداد أو ترحيل قاعدة بيانات أو أثر على البيانات المنشورة.
- **المراقبة:** لا يلزم إنذار تشغيلي لهذه المعالجة المتزامنة؛ تحذير React الناتج عن duplicate keys هو الإشارة التي يعالجها الاختبار الآن قبل النشر.

## التوافق والتراجع
- لا تغيير في API أو Schema أو مسارات المستخدم.
- التراجع، إن لزم، هو إعادة ملف المنطق السابق فقط؛ لا توجد بيانات تحتاج migration أو rollback.

## معيار القبول
1. عند غياب المنتجات، تظهر كل بطاقة جناح افتراضي مرة واحدة فقط.
2. لا تتكرر `id`/`slug` في بطاقات fallback.
3. إذا وُجدت منتجات، تبقى لها الأولوية ولا تظهر أجنحة fallback في القسم.
