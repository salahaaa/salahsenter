# تقرير تطوير العروض المجمعة بالكميات ومراجعة قبل النشر — 2026-07-03

## المشكلة
عند إنشاء عرض مجمع كتاجر، مثل:

```txt
3 دبات زيت + 2 كيس رز + 3 صحون تقديم
```

كان التاجر يستطيع اختيار الصنف مرة واحدة فقط، ولا يستطيع تحديد عدد القطع من نفس الصنف داخل العرض. كذلك لم تكن هناك مرحلة واضحة لمراجعة العرض قبل الإرسال/النشر.

---

## ما تم تنفيذه

### 1) إضافة كمية لكل صنف داخل العرض
تمت إضافة عمود جديد آمن إلى قاعدة البيانات:

```sql
store_offer_items.quantity integer default 1 not null
```

Migration:

```txt
drizzle/0032_store_offer_item_quantities.sql
```

وتم تطبيقه على قاعدة البيانات المشتركة.

---

### 2) تعديل نموذج إنشاء العرض للتاجر
تم تعديل:

```txt
components/merchant/store-offer-form.tsx
```

الآن جدول اختيار منتجات العرض يحتوي على:

- اختيار الصنف.
- رقم الصنف/الباركود.
- اسم الصنف.
- السعر الأساسي.
- **الكمية داخل العرض**.
- سعر عرض للوحدة.
- إجمالي السطر.
- الحالة.

وبذلك يستطيع التاجر بناء عرض مثل:

```txt
زيت × 3
رز × 2
صحون تقديم × 3
```

---

### 3) زر تجميع العرض قبل الإرسال
أضيف زر:

```txt
تجميع العرض
```

وظيفته:

- يحسب إجمالي السعر قبل العرض.
- يحسب إجمالي السعر بعد العرض.
- يعرض كل الأصناف والكميات.
- يعرض سعر الوحدة قبل/بعد.
- يعرض إجمالي كل سطر.
- يعرض نسبة التوفير التقريبية.

ولا يستطيع التاجر إرسال العرض قبل الضغط على زر التجميع ومراجعة التفاصيل.

---

### 4) تحكم شامل قبل الإرسال
بعد الضغط على "تجميع العرض" يستطيع التاجر:

- تعديل كمية أي صنف.
- تعديل سعر عرض أي صنف.
- تعديل سعر الباقة الإجمالي.
- تغيير طريقة الخصم بين مبلغ/نسبة.
- إضافة صنف آخر.
- حذف صنف من العرض.
- الضغط على تجميع مرة أخرى لإعادة الحساب.

ثم يرسل العرض للمراجعة.

---

### 5) تحديث API إنشاء العرض
تم تعديل:

```txt
app/api/merchant/offers/route.ts
```

ليقبل:

```json
{
  "productId": "...",
  "quantity": 3,
  "offerPrice": 100
}
```

ويحفظ الكمية داخل `store_offer_items.quantity`.

### آلية التسعير
- إذا كان الخصم نسبة، يحسب سعر الوحدة بعد الخصم.
- إذا كان سعر باقة إجمالي، يوزع سعر الباقة على إجمالي القطع.
- إذا أدخل التاجر سعر عرض خاص للوحدة، يتم اعتماده لذلك الصنف.

---

### 6) تحديث API تعديل العرض
تم تعديل:

```txt
app/api/merchant/offers/[id]/route.ts
```

حتى يدعم تعديل كميات الأصناف داخل العرض لاحقاً.

---

### 7) تحديث صفحة العرض العامة والشراء
تم تعديل:

```txt
lib/cache/public-offer-detail-cache.ts
app/offers/[id]/page.tsx
components/offers/offer-checkout-panel.tsx
```

الآن صفحة العرض:

- تعرض كمية كل صنف داخل العرض.
- تحسب إجمالي العرض بناءً على `السعر × الكمية`.
- عند شراء العرض، تُضاف الكميات الصحيحة إلى السلة.

مثال:

```txt
زيت × 3
رز × 2
صحون × 3
```

سيتم إضافتها للسلة بنفس الكميات.

---

### 8) تحديث قائمة العروض العامة
تم تعديل:

```txt
lib/cache/public-offers-cache.ts
```

حتى تعتمد إجمالي عدد القطع وليس فقط عدد الصفوف، وتحسب:

```txt
originalTotal = sum(originalPrice * quantity)
offerTotal = sum(offerPrice * quantity)
```

## النتيجة العملية

```txt
3 دبات زيت + 2 كيس رز + 3 صحون تقديم
```

```txt
تجميع العرض
```

ويراجع:

- التفاصيل.
- الكميات.
- السعر قبل العرض.
- السعر بعد العرض.
- التوفير.

ثم يقرر:

- تعديل السعر.
- تعديل الكميات.
- إضافة صنف.
- أو إرسال العرض.

وهذا يمنع إرسال عروض غير مضبوطة قبل مراجعتها.
