# تقرير تنفيذ: نقطة القرار المالي قبل تفعيل الظهور التجاري

**التاريخ:** 2026-07-15  
**الحالة:** مكتمل محلياً — ستضاف نتائج التحقق النهائي بعد الحزمة الكاملة.

## ما تم تنفيذه

### حالات مالية تشغيلية واضحة
لكل طلب تحول إلى حملة متوقفة، يضاف الآن checkpoint منفصل:
```text
awaiting_invoice → invoice_issued → payment_verified
```

- `awaiting_invoice`: أنشئت الحملة والاستحقاق، ولم تسجل الإدارة الإجراء المالي بعد.
- `invoice_issued`: سجل الأدمن مرجع فاتورة/إجراء مالي صادر.
- `payment_verified`: سجل الأدمن أنه راجع السداد في مسار المال المعتمد.

### التفعيل اليدوي محكوم بالخادم
حملة الظهور المرتبطة بطلب تاجر لا يمكن تحويلها إلى `active` من محرك الظهور ما لم تكن النقطة المالية:
```text
invoice_issued
```
أو:
```text
payment_verified
```

وهذا الفحص في API على الخادم، وليس مجرد تعطيل زر في الواجهة. الحملة التي أنشأها الأدمن مباشرة ولا ترتبط بطلب لا تتأثر بهذا الشرط.

### واجهة الإدارة
ضمن طلب «بانتظار التفعيل» يظهر قسم **نقطة القرار المالي قبل التفعيل**، حيث يسجل الأدمن:
- مرجع الفاتورة أو مرجع المراجعة.
- ملاحظة مالية.
- إصدار الفاتورة.
- ثم مراجعة السداد بعد تسجيل الفاتورة.

بعد ذلك يعود الأدمن لمحرك الظهور ويفعّل الحملة يدوياً في الوقت الذي يقرره.

### واجهة التاجر
يرى التاجر حالة الإجراء المالي بصورة وصفية فقط، مثل «تم تسجيل فاتورة صادرة» أو «تمت مراجعة السداد»، ولا يرى تفاصيل داخلية حساسة ولا يستطيع تعديل checkpoint أو التفعيل.

## الحوكمة المالية
- لا توجد بوابة دفع أو تحصيل أو payout جديد.
- لا يغير checkpoint حالة `ad_billing` إلى `paid` تلقائياً.
- المرجع والملاحظة لا يشكلان إثبات تحصيل تلقائياً؛ هما سجل قرار إداري مدقق.
- يبقى نموذج أموال العميل → التاجر مباشرة دون تغيير.

## البيانات
أضيف الترحيل:
```text
0074_home_exposure_financial_checkpoint
```

وهو يضيف الحالة والمرجع والملاحظة والمراجع والتاريخ وفهرساً تشغيلياً إلى `home_exposure_requests`.

## اختبار محدد
تمت إضافة اختبار يمنع تفعيل الحملة قبل إصدار فاتورة أو مراجعة سداد، ويمنع الانتقال مباشرةً من `awaiting_invoice` إلى `payment_verified`.

## حدود قبل Production
- لم تطبق migrations `0071`–`0074` على Staging أو Production.
- لا توجد تجربة PostgreSQL حية لمسار transaction/checkpoint/activation في Arena.
- لا يبدل هذا التغيير نظام تسوية الفاتورة المعتمد؛ يضيف فقط نقطة قرار إدارية قبل الظهور.
